## 4. 리뷰용 테스트 시나리오

> **추천 순서**: 먼저 고객 입장에서 구매 한 번 → 관리자 화면에서 처리 → 다시 고객 화면에서 확인

### 시나리오 A — "주문 받고 배송 보내기"

1. (고객) `test@parable-ent.com` 로 로그인
2. 아무 상품 → 옵션 선택 → 장바구니
3. 장바구니 → 체크아웃 → 샌드박스 결제 완료
4. **주문 번호 기억해두기**
5. 로그아웃 → `/admin/login` → `admin@parable-ent.com`
6. 사이드바 "주문관리" → 방금 그 주문 찾기 (최상단)
7. 상태 드롭다운 `결제완료` → `상품준비` → `배송중` 순서로 바꿔보기
8. "배송등록" 버튼 → 택배사 `CJ대한통운`, 운송장번호 `1234567890` 입력 → 등록
9. 고객 계정으로 다시 로그인 → 마이페이지 → 주문내역에 배송 정보가 반영됐는지 확인

### 시나리오 B — "리뷰 관리"

1. (고객) 구매확정된 주문에서 상품 리뷰 작성
2. (관리자) "리뷰관리" 탭 → 방금 쓴 리뷰 찾기
3. "숨기기" 버튼 → 공개 상태가 "비공개" 로 바뀌는지 확인
4. (고객) 상품 상세에서 해당 리뷰가 사라졌는지 확인
5. (관리자) 다시 "공개" 로 토글

### 시나리오 C — "쿠폰 발행"

1. (관리자) "쿠폰관리" → "쿠폰 생성"
2. 이름 `신규 리뷰어 할인`, 코드 `REVIEW10`, 10% 할인, 오늘 ~ 30일 뒤
3. 생성 성공 메시지 확인
4. (고객) 체크아웃에서 쿠폰 코드 `REVIEW10` 입력 시 할인 적용되는지 확인

### 시나리오 D — "Q&A 답변"

1. (고객) 상품 상세 → Q&A 탭 → 문의 작성
2. (관리자) "Q&A 관리" → 답변 대기 목록에서 해당 문의
3. "답변 작성" → 텍스트 입력 → "답변 등록"
4. (고객) 상품 상세에서 답변이 보이는지, 마이페이지 내 QnA 에서 답변 완료 표시되는지 확인

### 시나리오 E — "상품 숨기기"

1. (관리자) "상품관리" → 아무 상품의 "숨김" 버튼
2. 상태 배지가 "비활성"으로 변경 확인
3. 새 탭 열어 고객 쪽 카테고리 페이지에서 **해당 상품이 목록에서 빠졌는지** 확인
4. "노출" 토글로 복구

## 5. 피드백 수집 템플릿

리뷰어분께서 아래 형식으로 남겨주시면 바로 작업 리스트에 반영합니다:

```
[버그 / 개선 / 제안]  [페이지 또는 기능]
현상:
기대 동작:
재현 스텝:
스크린샷 (가능하면):
```

**예시:**

```
[버그] 주문관리 > 배송등록
현상: 운송장번호에 하이픈(-) 넣으면 등록 후 화면에서 빠짐
기대 동작: 입력한 그대로 표시되어야 함
재현: 1234-5678-9012 입력 → 등록 → 새로고침 → 123456789012 로 표시됨
```

## 6. 관리자 계정 복구가 필요할 때

비밀번호 분실이나 DB 초기화 등으로 관리자 계정이 날아간 경우, **로컬에서** (Cowork 샌드박스가 아닌 본 기기) 아래 명령으로 즉시 복구:

```bash
# .env.deploy.local 의 DATABASE_URL 사용
DATABASE_URL="postgresql://parable_app:<PW>@34.22.100.7:5432/parable_mall?schema=public&sslmode=require" \
  pnpm db:ensure-admin
```

기본값 외에 다른 이메일/비번으로 만들고 싶다면:

```bash
ADMIN_EMAIL="newadmin@parable-ent.com" \
ADMIN_PASSWORD="MyN3wP@ss!" \
ADMIN_NAME="운영자 A" \
ADMIN_ROLE="ADMIN" \
DATABASE_URL="..." \
  pnpm db:ensure-admin
```

`ensure-admin` 스크립트는 **멱등**이라 여러 번 실행해도 안전합니다 — 이미 있으면 비밀번호만 갱신, 없으면 새로 생성.

## 7. 알려진 제약사항 (보안/개인정보)

- **SSO Protection 현재 꺼둠** — 테스트 편의상. 외부 공유 전 반드시 재활성화 필요. 처리는 관리자 쪽에서. (`docs/DEPLOY-HANDOFF.md` 참조)
- **Cloud SQL `0.0.0.0/0` 허용 중** — Preview 테스트용 임시 조치. 상용 전 VPC Connector + Private IP 로 전환.
- **실 결제 키 미등록** — 테스트 카드 외 실제 카드 입력 금지.
- **PII 로깅 방지** — 주문자 이메일/전화/주소는 Sentry 스크러빙 대상이지만 Sentry 자체도 placeholder 키. 지금은 서버 콘솔 로그에만 남음.
